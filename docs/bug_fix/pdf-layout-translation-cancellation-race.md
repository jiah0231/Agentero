# PDF 布局翻译：取消后的迟到结果覆盖新任务

## 范围与现象

在 `fix/layout-translation-completeness-20260906` 分支的 `e87c351d` 基线上，
整篇和单页翻译都可能在请求取消后继续返回最终结果，造成以下问题：

- 停止后立即重试，旧任务把新任务的状态改回 `cancelled`。
- 清空译文或切换文档后，旧译文重新出现在阅读器中。
- 旧任务的最终结果再次安排 sidecar 写入，干扰新任务的缓存更新。
- 停止或切换页任务后，未完成的块仍标记为 `running`，页面按钮继续显示运行中，
  下一次点击只会再次停止，而不是立即重试。

## 原因

`use-pdf-layout-translate.ts` 已在进度回调中检查 `AbortSignal`，但在
`await runLayoutRegionTranslate(...)` 返回后，先持久化结果，再处理取消状态。
被取消的任务仍会调用 `setLayoutTranslateJob`。停止操作只修改任务级状态，
没有同步释放块级的 `running` 状态。

取消请求不等于请求已经结束，界面不能依赖旧 runner 最终返回来完成取消清理。

## 修复

整篇和单页路径均在最终结果写入前检查：请求未取消，且其 `AbortController`
仍属于当前任务。失去所有权的任务直接返回，不再更新界面或安排最终缓存写入。
已有的进度回调、错误回调与 `finally` 所有权检查继续保留。

停止时立即把运行中的块恢复为 `pending`；启动新的单页任务时也释放其他页中
被中断的块。已完成的块和译文保留，未完成块可立即重试。

本修复不变更翻译提供商、缓存格式或安装包版本，也不处理已开始执行的磁盘写入。

## 回归验证

测试文件：`test/pdf-layout-translate-lifecycle.test.ts`。

```sh
pnpm exec vitest run test/pdf-layout-translate-lifecycle.test.ts
```

12 个场景覆盖整篇重启、单页替换、停止后立即重试、成功块保留、清空、切换文档、
组件卸载、迟到进度与错误，以及当前任务正常完成和缓存写入。
测试通过 TypeScript 编译实际 hook，并使用确定性的 hook 状态槽与可控 Promise，
不需要浏览器或 Tauri。它验证异步任务边界，不代替 React 调度器或桌面端到端测试。

本地用 Node 测试运行器执行同一组测试时，原始代码为 2 通过、10 失败；
修复后为 12 通过、0 失败。仅测试注册入口由 Vitest 替换为 Node，断言与被测代码不变。
新增测试文件另通过 TypeScript 5.8.3 严格检查。
